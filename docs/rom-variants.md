# ROM正規化の内部仕様（1.0.2）

機能判定は確認済みPRG全体のSHA-256による。ファイル名には依存しない。読み込み時のメモリ上で既知のヘッダー・末尾情報・重複収録を正規化し、元ファイルと保存識別子は保持する。具体的なファイル名・識別値・サンプル一覧は掲載しない。

## 正規化と機能の接続

DQ3のMapper 2変換に伴う命令変更は保持する。末尾の付加情報とヘッダーの予約領域を補正し、PRG自体は変更しない。

DQ4は完全一致する先頭512 KiBを使う。重複部分が不完全な既知データは元ファイル全体も照合してから限定的に除去する。未知の追加コードは除去しない。

FF2ではタイトル文字列16バイトだけが異なり、実行コードと音声データが一致する場合に既存の接続を適用する。

FF3では音声・戦闘報酬・ジョブ・メニュー入力が使うバンク26・27・30と固定バンクの入力処理を照合する。既知のリセット処理のパッチは保持する。PRG全体の内容照合で適用対象を限定し、改変データ自体は修復しない。

## 適用しない条件

プログラムの欠損・位置ずれ、機能の接続先の相違がある場合はプロファイルを適用しない。改行コードを除去するだけで元に戻らないデータも推測で補修しない。未知の改変PRG、トレーナー付き、CHR ROM付き、未知の追加バンクも対象外とする。

## 検証方法

識別、対応外データの保持、正規化の再実行、元ファイル・PRGの保持、未知のPRG・欠損・追加バンクの拒否を検査する。FF3では機能用バンクの一致も確認する。

アプリの検査経路で1〜6倍、映像・音声を含む保存復元、旧形式ステート、破損ステート拒否、SRAMを検査する。入力・音声・報酬倍率・熟練度・ジョブ変更は専用テストで確認する。長時間の全編プレイ・Android実機の確認とは区別する。
